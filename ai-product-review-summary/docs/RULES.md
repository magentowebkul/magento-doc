Workspace Guidelines & Constraints

1. Version Control & Git Restrictions

No Git Actions: Do NOT execute any git commands, including but not limited to git add, git commit, git push, git pull, git checkout, or git status. All version control operations are handled externally.

2. Directory & Scope Access

Current Directory Access: You have read-write-execute access only to the root directory where you are currently operating.

Target Module Access: You have read-only access to the external module/codebase you are tasked to work with or reference. Do NOT attempt to write, modify, or delete files outside the current working directory.

3. Communication & Output Rules

No Unnecessary Summaries: Avoid lengthy explanations, polite filler text, meta-commentary, or redundant summaries. Keep all responses brief and direct.

Context Preservation: Prioritize keeping the conversation context clean, focused, and concise to maximize efficiency and preserve context window limits.

Action-Oriented: Provide code, edits, or answers directly without preambles or post-reflections unless explicitly requested.

4. Execution & Code Generation

Ensure all generated code and files are complete and non-destructive to the allowed working directory.

Verify file boundaries and do not modify files outside your given explicit permissions.
